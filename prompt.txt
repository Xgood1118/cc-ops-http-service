背景：仓库里是一个用 Python 标准库实现的内部运维 HTTP 服务（位于 tools/ 目录），通过几个 HTTP 接口给内网同事提供文件读取、主机诊断和数据加载能力。团队怀疑该服务存在可被远程利用的安全问题，需要你做一次完整的安全评估并给出可落地的修复。不要重写整个服务，保持现有接口、路由和目录结构；仅用 Python 标准库，不引入第三方依赖。

任务：
1. 通读服务代码，定位所有可被远程利用的安全问题。对每个问题给出：漏洞位置（文件、函数、行号）、根因与完整攻击路径、以及可直接运行的复现步骤和 PoC（用 curl 或本地脚本，给出完整请求与预期响应）。
2. 对每个确认可利用的漏洞，在保持正常业务功能不变的前提下完成修复，并补充回归验证：攻击用例必须失败、对应的正常业务用例必须通过。
3. 对看起来危险但当前实际不可利用的代码，单独说明为什么不可利用，不要当成漏洞误报。
4. 把发现、复现命令、修复说明和验证结果整理成一份评估报告，放在仓库根目录。
5. 运行全部现有测试和你新增的验证，确认真实通过；禁止通过删除或弱化测试来制造通过，禁止宣称修复但实际未改动。

约束：
- 所有 PoC 必须能在本机真实跑通，不接受只给理论描述。
- 保留现有公开接口的入参和返回结构，不能为修复把正常功能改坏。
- 全程仅用标准库；密钥、连接串等不得写进提交内容。
